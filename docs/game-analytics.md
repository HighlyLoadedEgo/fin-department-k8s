# Продуктовая аналитика игры

В Grafana два связанных дашборда:

- **Как играют дети** (`/d/children-play`) — рост аудитории, решения,
  трудности по навыкам и прогресс. Ссылка на подробности сохраняет период.
- **Экономика и данные игры** (`/d/game-analytics`, прежнее название —
  «Игровая аналитика») — суммы в монетах, аксессуары, игровые действия
  и синхронизация. UID и существующие ссылки сохранены.

## Откуда берутся данные

Backend публикует метрики через `/metrics`; PodMonitor
`apps/hackaton-fin-department/pod-monitor.yaml` передаёт их в Prometheus.
ConfigMap с `grafana_dashboard: "1"` подхватывает Grafana sidecar.

В backend есть два разных источника:

1. Событийные counters (`fin_*_total` для загрузок, регистраций, наград,
   новых фактов) увеличиваются после обработки запросов. Для общего потока
   используем `sum(rate(...))`, для периода — `sum(increase(...))`.
   Повторная загрузка пакета аналитики не увеличивает счётчики его фактов.
2. Периодический Aggregator читает PostgreSQL и заново публикует gauges:
   миры, последние проекции навыков, сохранённые факты и текущие балансы.
   Они могут уменьшаться. `_total`, `_bucket`, `_sum` и `_count` в имени
   сами по себе не делают эти метрики counters или временными гистограммами.
   `rate()` к ним неприменим. Реплики читают одну БД: такие gauges не суммируем.

В обзоре запросы ограничены `namespace="hackaton-fin"`.

## Что означают показатели

| Показатель | Расчёт и единица наблюдения |
| --- | --- |
| Верные ответы | Правильные / все сохранённые ответы в практиках. Ответы, не дети. |
| Трудности по навыку | DIFFICULTY / (SUPPORTED + DIFFICULTY + NEUTRAL). Отдельно для FIN-01…FIN-12. |
| Успехи без игровых подсказок | SUPPORTED без игровых подсказок / все SUPPORTED. Помощь взрослого не установлена. |
| Сколько ситуаций учтено | Число исходов SUPPORTED + DIFFICULTY + NEUTRAL по навыку: сумма средних × число оценённых прогонов. Знаменатель доли трудностей. Доля успехов без подсказок использует только успешные исходы. |
| Какие ситуации пока нельзя оценить | Количество ситуаций: ещё не завершены / недостаточно свидетельств. Категории могут пересекаться. Не складывать и не называть отвалом. |
| Отказ от покупки | Отказы / все решения о необязательной покупке. Высокая доля сама по себе не означает успех. |
| Использование резерва | Решения использовать резерв для неожиданного расхода / все решения об использовании резерва. |
| Доля бюджета на накопления | Все монеты в savings / все монеты в подтверждённых распределениях. Не среднее по детям. |
| Баланс ≤ 0 | Миры с нулевым или отрицательным доступным балансом / все распознанные миры с балансом. |
| Главы | Распределение сохранённых миров по текущей главе. Не воронка прохождения. |
| Завершённые проекты | Число завершений по идентификатору цели в текущих сохранённых мирах. |
| Новые события за период | Оценка прироста серверных counters. Время приёма может отличаться от времени игры. |
| Рост аудитории | Временной график gauges профилей, миров и прогонов; без `rate()` или `increase()` на gauges. |
| Завершения мини-игр | Сохранённые interaction-факты с именами CompleteStoryGame и CompleteDeed, отдельно от SkipMiniGame. Это количество команд, не уникальные дети. Демо внутри других команд не отделено. |

Доли без знаменателя или с нулевым знаменателем показывают «Нет наблюдений».
Если известны только неправильные ответы, доля верных — 0%, а не пропуск.
Рядом с долями показаны размеры выборки: ответы, решения и средние эпизоды.
Показатели навыков скрыты, если число оценённых прогонов равно нулю.
Размеры выборок и неполные ситуации доступны в открытом по умолчанию блоке
«Качество данных — для проверки выводов». Они помогают оценить достаточность
наблюдений; это диагностические показатели, а не результаты обучения.

Старый показатель «Мини-игры на игрока» удалён: `completedMiniGames`
содержит идентификаторы старых самостоятельных игр. Текущие сюжетные
мини-игры и подработки завершаются командами движка и этот список не
обновляют. Среднее с округлением до целого дополнительно скрывало малые
дробные значения. Новая панель считает соответствующие сохранённые факты.

## Где данные пересекаются

Аудитория, главы, проекты и правильность ответов теперь представлены
только в обзоре. Их прямые копии из подробного дашборда убраны.

Оставшиеся общие источники используются для разных вопросов:

| Общий источник | Обзор поведения | Экономика и данные |
| --- | --- | --- |
| `fin_budget_amount_stored` | Процент накоплений и доли статей | Панель удалена: проценты только в обзоре поведения |
| `fin_pet_balance_bucket/count` | Доля миров без свободных монет | Полное распределение балансов и среднее |
| `fin_rewards_issued_total` | Число новых наград за период | Скорость выдачи и подтверждения наград |
| Счётчики загрузок | Новые принятые события за период | Скорость загрузок и повторов |
| `fin_aggregation_last_success_unixtime` | Свежесть в блоке качества | Контроль работы агрегатора |

Показатели из двух дашбордов нельзя складывать: это разные представления
одних источников. Поток новых принятых фактов (`fin_analytics_facts_total`)
и запас сохранённых фактов (`fin_facts_stored`) — разные величины: второй
пересчитывается из текущих сохранений/проекций и не является вечным счётчиком.

## Ограничения интерпретации

- Профиль устройства, игровой прогон, мир и ребёнок — разные сущности.
  DAU/MAU, retention и уникальные дети здесь не вычисляются.
- Доступна только синхронизированная история. Offline-игра поступает позднее.
- Агрегатор использует последние проекции на пару профиль / прогон; это не
  полная неизменяемая история всех действий ребёнка.
- Выбор периода влияет на графики и блок новых событий. Instant-панели
  показывают текущие gauges. Они не становятся когортой выбранного периода.
- История Prometheus хранится 3 дня. Более длинный период неполон.
- `increase()` экстраполирует значения: возможны дробные оценки количества
  событий. Counters с labels создаются лениво; самое первое событие до
  первого scrape может не попасть в прирост. Отсутствующий ряд не означает 0.
- Средние исходных метрик навыков включают все оценённые прогоны. Панели
  размера выборки восстанавливают количество умножением на число прогонов.
  Сравнение сложностей требует достаточной выборки.
- «Возраст данных» показывает давность последнего успешного пересчёта.
  При устаревании или недоступном сборе сначала проверять источник.

Для удержания, длительности сессий, реальной воронки и повторных посещений
нужны события сессий/этапов с временем игры и когортный расчёт. Текущие
распределения глав и счётчики загрузок не заменяют эти данные.

## Проверка изменений

```bash
python3 tests/monitoring/check_dashboards.py --docker
kubectl kustomize infrastructure/base/controllers > /tmp/fin-controllers.yaml
```

Первой команде нужны Python 3, PyYAML и Docker. Она запускает закреплённый
`prom/prometheus:v3.5.0` без сети, проверяет PromQL всех панелей через
promtool и вычисляет настоящие запросы на контрольных данных. Без `--docker`
используется локальный `promtool`.

Визуальная проверка выполнялась в локальной Grafana 12.3.0 с явно
помеченными демонстрационными данными. Это не проверка production-значений.
